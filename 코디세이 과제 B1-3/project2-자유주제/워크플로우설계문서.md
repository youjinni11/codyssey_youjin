# 프로젝트 2: 자유 주제 자동화 설계 및 구현

## 1. 반복 업무 정의
매일 여러 통 도착하는 이메일 중 일정/미팅 관련 메일과 업무/공지 관련 메일을 매번 직접 열어보고 분류해서 확인하는 반복 작업을 자동화합니다. 이메일이 도착하면 자동으로 내용을 분류하여 Discord로 알림을 보내, 중요한 메일을 놓치지 않고 빠르게 확인할 수 있도록 합니다.

## 2. 도구 선정 및 이유
**선정 도구: Make**

- 하나의 시나리오 안에서 Router를 이용해 여러 조건 분기를 동시에 관리할 수 있어, 이메일 키워드에 따른 다중 분류 로직을 한 화면에서 설계하고 유지보수하기 용이합니다.
- 무료 플랜(월 1,000 Operations)으로도 충분히 구현 가능해 비용 부담이 없습니다.
- 실행 후 각 모듈의 Input/Output을 상세히 확인할 수 있어, 자동화가 의도대로 동작하는지 디버깅하기 편리합니다.

## 3. 워크플로우 흐름 설명
1. **Trigger**: Gmail (Watch Emails) — 받은편지함에 새 메일이 도착하면 감지합니다.
2. **조건 분기 (Router)**
   - **1번째 경로**: 제목/본문에 "일정", "미팅", "회의" 키워드가 포함된 경우
   - **2번째 경로**: 제목/본문에 "업무", "공지", "요청", "안내" 키워드가 포함된 경우
3. **Action (경로별)**
   - 일정 관련 경로 → Discord DM 전송: "📅 일정 관련 메일 도착: [제목] / [내용 요약]"
   - 업무 관련 경로 → Discord DM 전송: "📋 확인 필요한 메일 도착: [제목] / [내용 요약]"

## 4. 워크플로우 다이어그램

```
Gmail (신규 메일 감지)
        │
        ▼
     Router
     ├─ 조건: 제목/본문에 "일정", "미팅", "회의" 포함
     │     └─→ Discord DM: "📅 일정 관련 메일 도착: [제목] / [내용 요약]"
     │
     └─ 조건: 제목/본문에 "업무", "공지", "요청", "안내" 포함
           └─→ Discord DM: "📋 확인 필요한 메일 도착: [제목] / [내용 요약]"
```

## 5. 실행 결과
- Gmail 트리거가 실제 수신 메일을 감지하여 Router의 두 분기 모두 정상적으로 실행되는 것을 확인했습니다.
- 각 분기별로 Discord에 알림 메시지가 정상적으로 수신된 것을 확인했습니다. (구현 화면 및 실행 결과 캡처 첨부)

## 6. 향후 개선 아이디어 (선택)
- 현재는 이메일 원문 스니펫을 그대로 알림에 전달하지만, 추후 생성형 AI(Claude 등)를 Action으로 추가해 이메일 내용을 자동으로 한 줄 요약해서 전달하도록 확장할 수 있습니다.
- 워크플로우 실행 중 오류가 발생했을 때 별도의 이메일/메신저로 실패 알림을 받는 에러 핸들링 경로를 추가하면 안정성을 더 높일 수 있습니다.
